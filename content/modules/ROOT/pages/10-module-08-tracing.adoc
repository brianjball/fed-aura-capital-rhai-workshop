Monitoring and measuring every AI decision.

Fed Aura Capital is running agentic AI for risk assessments. Regulators require full traceability. The CTO needs to know if the AI is making correct recommendations, what tools it called, how long each step took, and whether prompt changes cause regressions. Without observability, the system is a black box. With MLflow tracing and EvalHub, every agent decision is recorded, measurable, and auditable.

When you are hosting your own LLMs, you are responsible for maintaining performance. When performance starts to degrade, you need to be able to understand why. It could be due to GPU performance, cache hit rate, kueue length, or any number of reasons. The dashboards provided here will help you identify the problem, then drill down into the potential reasons so that you can remediate them.

=== Implementing MLflow Traces

MLflow now has native support for Kubernetes. Furthermore, the tracing is also nearly automatic. As long as your Python application is running in OpenShift, you only need a few items to integrate it.

First, you will need to pip install `mlflow[kubernetes]`. This package handles all of the gritty details for you. In your Python code, you only need three lines from here:

```Python
import mlflow
import os

mlflow.set_tracking_uri("your-mlflow-url")  # Tell your application where MLflow is running
os.environ["MLFLOW_TRACKING_AUTH"]="kubernetes-namespaced"  # Tell it you're running in Kubernetes and it will automatically handle namespace-level multitenancy
mlflow.openai.autolog()  # Enable tracing
```

OpenShift AI comes with a ClusterRole that manages the permissions to enable the integration. The role is called "mlflow-operator-mlflow-integration". So long as you bind your service account to this role, the code will work.
