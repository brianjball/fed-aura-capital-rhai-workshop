== Exercise 1: Explore the Model Catalog

Browse the OpenShift AI Model Catalog, filter by task type, and identify NVIDIA Nemotron models available for deployment.

=== Find the model catalog

.To find the model catalog from OpenShift AI, click on "AI hub", then "Models". From the new page, click the "Catalog" tab.
image::model-catalog-navigation.png[The model catalog link in OpenShift AI,align=center]

From the model catalog, you can filter multiple different ways. The easiest way is to have "All models" selected and then use the filter. Different collections appear directly below the filter, for example "Red Hat AI - validated models" that come from third parties or "Red Hat AI models" that come directly from Red Hat. You can also search by tags on the left hand side.

In this case, let's do a filter on "Nemotron" and see what we get:

== Exercise 2: Deploy a Model on GPU

Walk through the Deploy wizard, select a GPU hardware profile, and configure a vLLM ServingRuntime for inference.

We will start by creating a hardware profile. Navigate to Settings (the last option in the sidenav) > Environment setup > Hardware profiles.

image::hardware-profile-settings.png[Hardware profiles link in OpenShift AI,align=center]

We will create a new hardware profile. Give it the name "NVIDIA GPU", then find the "Resource requests and limits" section. Add a new resource and give it the values shown below:

.You can use the default maximum provided of 2, or you can set it to 1. Our clusters only have 1 GPU on them so you can't actually allocate more anyways.
image::gpu-resource.png[GPU configuration,align=center]

We also need to increase the memory allowance for the hardware profile. Modify the Memory default and maximum to 6Gib and 8Gib respectively.

Click create hardware profile when you are done.

=== Deploy GPT OSS 20B

Navigate back to the model catalog and find the catalog item "gpt-oss-20b-essential"

image::gpt-oss-20b-essential.png[GPU configuration,align=center]

Click into the item and familiarize yourself with the page. Note the description of the model, the model location, and performance insights based on tests Red Hat has done. When you are ready, click "Deploy model". This will take you to a wizard.

1. Preconfigure deployment
    - Select the "models-as-a-service" project from the dropdown.
2. Model details
    - Verify that this is a Generated AI model.
3. Model deployment
    - Set the model deployment name to "gpt-oss-20b"
    - Select "LLM inference service with llm-d" as the Deployment method. This workshop won't be able to show the benefits of llm-d over base vLLM, but know that you can easily measure the differences even with a small handful of replicas. Notice that OpenShift AI makes it just as easy to deploy llm-d in the base configuration!
    - Select the NVIDIA GPU hardware profile we just created.
    - Deploy a single replica.
4. Advanced settings
    - Set the first several options as in the image below. In particular, make sure that the AI asset endpoint and MaaS boxes are checked as they will be needed for the remainder of the workshop.

image::gpt-oss-deployment-options.png[Advanced settings in the GPT OSS deployment,align=center]

When you are ready, click deploy. The model will take several minutes to download and deploy, so please be patient!
