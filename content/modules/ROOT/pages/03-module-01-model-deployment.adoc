Model choices and compression - smaller size, same intelligence.

Lenora depends on language models for every conversation, reasoning step, and tool decision.
In the complete platform architecture, those models sit behind the MaaS gateway and provide inference to all five persona-specific agents.
This module zooms in on that model-serving layer.

.Module 1 focus: self-hosted model inference
image::fed-aura-platform-architecture-models-focus.svg[The Fed Aura Capital platform architecture with the self-hosted models layer highlighted,align=center]

Fed Aura Capital wants to replace per-token dependence on external model vendors with private, self-hosted inference.
You will browse the Red Hat OpenShift AI Model Catalog, deploy models on CPU and GPU, scale inference with llm-d, and measure the effect of quantization on latency.
The endpoint produced here becomes the intelligence layer that later modules govern, connect to tools and knowledge, observe, and secure.

Estimated time: *25 minutes*

== Learning Objectives

By the end of this module you will be able to:

* Navigate the RHOAI Model Catalog and identify validated models
* Deploy an LLM on CPU and understand hardware profile selection
* Deploy with GPU and llm-d distributed inference
* Benchmark quantized vs unquantized models and interpret TTFT metrics

== Module Summary

=== What You Accomplished

* Browsed the RHOAI Model Catalog and located validated Nemotron models
* Deployed an LLM using both CPU and GPU hardware profiles
* Enabled llm-d distributed inference with configurable replicas
* Ran quantized vs unquantized benchmarks and measured TTFT improvements

=== Key Takeaways

* Quantized models deliver comparable quality at significantly lower latency (1.69x speedup in TTFT)
* Self-hosted inference eliminates per-token costs and keeps data inside the cluster
* llm-d provides scalable, distributed inference without manual load-balancing
