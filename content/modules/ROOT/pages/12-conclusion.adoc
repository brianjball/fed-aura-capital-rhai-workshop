Congratulations! You have completed the Fed Aura Capital AI Workshop and built a production-ready AI platform on Red Hat OpenShift AI.

== What you accomplished

Throughout this workshop, you progressed through four transformation waves, taking Fed Aura Capital from a prototype chatbot to a production-grade, observable, and secure AI system.

=== Wave 1 - Inference: "From token consumer to token producer"

* Deployed LLMs from the RHOAI Model Catalog on both CPU and GPU
* Benchmarked quantized vs unquantized models, measuring a 1.69x TTFT speedup
* Scaled inference with llm-d distributed serving
* Published models as managed services with subscription tiers and API key governance

=== Wave 2 - Data: "From generic to useful AI"

* Shaped model behavior with domain-specific system prompts in the GenAI Playground
* Trained a predictive underwriting model with AutoML achieving 91.7% accuracy
* Grounded responses in private policy documents with RAG
* Explored OGX capabilities for advanced data workflows

=== Wave 3 - Agentic: "From useful to productive AI"

* Connected agents to real tools via MCP servers registered as Kubernetes resources
* Traced every agent decision end-to-end with MLflow, from input shield through tool calls to output shield
* Ran automated evaluation pipelines to catch regressions before production

=== Wave 4 - Safety: "From prototype to production-grade"

* Deployed NemoGuardrails for runtime input/output protection
* Reviewed Garak adversarial test results validating model robustness
* Explored OpenShell for secure agent onboarding with deny-by-default sandboxing, SPIFFE/SPIRE identity, and OCSF audit

== Key takeaways

1. *The platform is the product.* Individual AI capabilities (inference, RAG, agents) are powerful alone, but their value multiplies when integrated on a single platform with shared observability and governance.

2. *Zero to Hero is achievable.* Every module started from nothing and built a real capability. AutoML trains models without ML engineering. MaaS publishes models without custom infrastructure.

3. *Contrast drives understanding.* By showing what life looks like without each capability, you can articulate the business value of every investment in the AI platform.

4. *Safety is not optional for production.* Defense-in-depth (NemoGuardrails + Garak + OpenShell) provides the security posture needed to move from "prototype approved" to "production deployed."

5. *Observability enables trust.* When regulators ask "why did the AI recommend this?", MLflow traces provide a complete, reproducible answer.

== Next steps

* *Start with inference*: Deploy a model from the catalog and publish it as MaaS for your team
* *Ground in your data*: Upload your organization's policy documents via the Knowledge tab
* *Trace everything*: Enable MLflow autolog and start building your trace corpus
* *Evaluate before shipping*: Build an evaluation pipeline and run it before every prompt change
* *Secure your agents*: Define OpenShell policies for your agent deployments
